# Demos & reproduction guide

agentvcs keeps an agent's whole **history** — every iteration as a commit, with a
quality score attached. That lets it answer questions a live runtime can't: *is the
self-modification loop improving or quietly rotting? Is a branch worth keeping? Is a
shared memory safe?* These demos show that end to end.

There are two, and they are the same five capabilities told two ways:

| Demo | Audience | Run |
| --- | --- | --- |
| [`examples/business-cases/`](../examples/business-cases/) | **Start here.** Non-technical — five business stories, one-line recommendations, no math on screen. | `bash examples/business-cases/run.sh` |
| [`examples/evolution-diagnostics/`](../examples/evolution-diagnostics/) | The technical companion — the real numbers, the theory, and every claim asserted against `--json`. | `bash examples/evolution-diagnostics/run.sh` |

Live, navigable versions are on the site:
**https://evolvingagentslabs.github.io/agentvcs/demos/**

Everything is **real**: a deterministic benchmark (`bench.py`, generated by each script)
scores the agent, `agentvcs eval` records the score, and the diagnostics read only the
commit graph and the eval side-table. No numbers are faked.

## Prerequisites

Python 3.10–3.13. No install required — the scripts fall back to running agentvcs from
`src/` — but installing is fine too:

```bash
git clone https://github.com/EvolvingAgentsLabs/agentvcs
cd agentvcs
pip install -e .            # optional; the demos also run straight from source
```

## Run them

```bash
bash examples/business-cases/run.sh          # plain-English stories
bash examples/evolution-diagnostics/run.sh   # technical, self-asserting
```

Each script rebuilds its own throwaway sandbox under `workdir/` (git-ignored) from
scratch, so you can run them any number of times. The technical demo prints a green `✓`
for every assertion and ends with **"All five acts asserted green."** — if a tool ever
regresses, the script exits non-zero.

## The five capabilities

| # | Command | What it measures | The call it makes |
| --- | --- | --- | --- |
| 1 | `agentvcs price` | Price-equation decomposition of the quality change: **selection** (`Cov(w,z)`, choosing between branches) vs **transmission** (`E[w·Δz]`, editing within a lineage), plus the Eigen error-catastrophe verdict. | "Your self-updates are net-negative — roll back" vs "genuinely improving — keep going". |
| 2 | `agentvcs price` (branched history) | Same, on a branch-and-select history. | Selection now positive → the fix for a rotting loop is branch-test-keep, not more editing. |
| 3 | `agentvcs branch` / `merge` | Muller's-ratchet load on a long unmerged lineage (divergence + deleterious steps). | "This fork has drifted alone too long and is degrading — merge it back." |
| 4 | `agentvcs infobits` | The decision channel from the trace: `H(action)` and `I(prev; next)` bits (a labeled lower-bound proxy for `I(context; action)`). | "This context barely moves the decision — trim it to cut cost/latency." |
| 5 | `agentvcs contain` | Branching-process `R₀ = n·p` for shared-memory poisoning (fan-out from the swarm, escape rate from the failed-eval fraction). | "A bad entry will spread — verify N% of reads, or shrink the fleet." |

## Reproduce a single capability by hand

The commands work on any agentvcs repo that has a few commits with recorded evals:

```bash
agentvcs price --json        # selection vs transmission + threshold verdict
agentvcs health --json       # price + critical-slowing-down + ratchet, one warnings[]
agentvcs branch --json       # per-branch ratchet risk + merge-me warnings
agentvcs infobits --json     # bits the decisions carry (needs a trace with tool_use)
agentvcs contain --json      # R0 for a declared swarm + failed-eval rate
agentvcs contain --fanout 3 --prob 0.2 --json   # or supply n and p directly
```

Declare an editable surface in `agent.json` to have `price`/`threshold` size the Eigen
bound against *that*, not the whole spec:

```json
"editable": ["skills/", "prompts/planner.md"]
```

## The theory (optional)

The full design, the population-genetics mapping, and the honest scope boundary (what
belongs to a VCS vs. a live harness) are in
[`EVOLUTIONARY_DYNAMICS.md`](EVOLUTIONARY_DYNAMICS.md). The short version: these are
measurements over a recorded **population of variants across time** — the one object a
version control system owns and a controller doesn't. The math is real; the
decision-maker never has to see it.
