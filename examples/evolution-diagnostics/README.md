# evolution-diagnostics — proving self-modification is *actually* working

```bash
bash examples/evolution-diagnostics/run.sh
```

A version control system is the only thing that holds an agent's whole **lineage** —
every iteration as a commit, with an eval score attached. This example uses that, and
nothing a live harness has, to answer questions a harness can't:

> *Is my agent's self-modification net-positive, or is it rotting?
> Is a branch worth keeping? How much context is actually informing the decision?
> Will a corrupted shared memory contain itself?*

Everything below is **real**: a deterministic benchmark (`bench.py`, generated by the
script) scores the router the "agent" edits, and `agentvcs eval` records those scores.
The diagnostics then read only the commit graph and the eval side-table. Every claim in
the narration is **asserted** against `--json` output — the script fails loudly if the
tools ever stop earning it.

## The five acts

| Act | Command | The "aha" |
| --- | --- | --- |
| **1. The loop that was quietly rotting** | `agentvcs price` | An agent tunes a router by editing one file, never branching. All five commits pass their eval (bench ≥ 0.5), so *nothing commit-to-commit looks wrong*. But `price` runs the **Price equation** over the lineage: `selection = 0` (no branches → zero by construction) and `transmission = −0.1` (within-line editing is net-negative). That is the **Eigen error catastrophe** — visible only at the lineage level. |
| **2. The cure is recombination** | `agentvcs price` | Same agent, same benchmark — but now it **forks** two variants each round, keeps the better, and invests exploration in the winner. `selection` goes positive, `transmission` goes positive, verdict flips to **healthy**. The fix for a rotting loop isn't more editing; it's branch-and-select — exactly what agentvcs makes cheap. |
| **3. Muller's ratchet** | `agentvcs branch` / `merge` | A feature branch evolves in isolation and slowly loses fitness. Plain `agentvcs branch` flags it — *"long unmerged lineage (5 commits, 4 deleterious steps) losing fitness — merge it back to reconstitute the least-loaded class."* An asexual lineage can't purge deleterious edits; **merge is the recombination that ends the isolation**, and the ratchet flag clears. |
| **4. The value of context, in bits** | `agentvcs infobits` | Two agents, 30 tool calls each. The near-deterministic one's decisions carry **0.42 bits**; the varied one, **2.58 bits**. By Kelly/Kussell–Leibler the value of extra context is bounded by the bits it adds to the decision — so the 0.42-bit pipeline has a *quantified* license to compress its context hard. (The mutual information is honestly labeled a lower-bound proxy — context = previous action.) |
| **5. Containing a poisoned memory** | `agentvcs contain` | A fleet of 6 readers shares a memory; 2 of 5 recorded states failed their eval. The branching-process test `R₀ = n·p = 6 × 0.4 = 2.40 ≥ 1` says corruption is **not** self-limiting — and hands you the fix as a number: **verify ≥ 58 % of reads**, or shrink the fleet (`--fanout 2` → `R₀ = 0.8`, contained). |

## Why this is the point of agentvcs

None of these are harness features. They're **measurements over a recorded population of
variants across time** — the one object a VCS owns and a controller doesn't. `price`
turns "is the agent improving?" from a vibe into `Cov(w,z)` vs `E[w·Δz]`; `contain` turns
"is our shared memory safe?" into a verification rate. All of it from data agentvcs was
already storing, standard-library-only, with `--json` for agents.
